## What changed in the build

`load_articles()` in `build.py` used to copy the newest attached YouTube video's `published` time onto the article as `updated` whenever that time was later than the article's own date. That value was not written back to the JSON, but the build used it for two public dates:

- NewsArticle JSON-LD `dateModified`
- the article URL's `<lastmod>` in `sitemap.xml`

Attaching a video is not an edit of the article body, so that copy no longer happens. `dateModified` and the article sitemap `lastmod` now come only from the article file: `updated` when the file sets it, otherwise the publication `date` and `time`. None of the current article files set `updated`, so both dates follow publication until a real text edit does.

Other sitemap URLs (the homepage, category and model pages, the archive, Shorts and the static pages) still use the date of the build as `<lastmod>`. Those are not an article's `dateModified`. A rebuild refreshes them even when no article text changed.

The house rule is now in the README (`House rule: publication dates`) and in `ops/tasks/article.md`: `date` and `time` are the actual publication moment in Europe/Amsterdam, and `updated` is set only when the body really changes.
