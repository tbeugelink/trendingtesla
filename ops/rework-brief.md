# Rework brief: video storyline + fact check for trendingtesla.com articles

Work in the repo checkout you were given (do NOT run git, do NOT run build.py, do NOT touch any file other than the article JSON files assigned to you and your report file).

Articles are JSON in content/articles/. Two finished reference examples that already follow the new structure — read both fully before starting:

- content/articles/2026-10-24-how-starlink-works-satellites-lasers-dish-explained.json
The exact writing rules used for new articles are in the section "Writing rules" at the end of this file. Follow them.

For EACH assigned article:

## 1. Fact check (do this first)
- Read the article (en + nl) and its sources. Fetch the listed sources with WebFetch where possible, and use WebSearch to verify every key number, date, name and claim.
- Judge the article as of its own publication date ("date" field). An article is not wrong because things changed later.
- Fix real errors (wrong number, wrong date, wrong name, claim not supported by any source, mistranslation between en and nl, en and nl disagreeing). If a claim cannot be verified, soften it ("reportedly", "according to X") or remove it.
- Additions: only when an important directly related fact was missing at the time, or when the story's central point was later clearly settled/overturned (e.g. a promised launch did or did not happen). In the latter case add ONE short paragraph at the very end of the body (before any financial-advice disclaimer): EN `<p><em>Update (D Month YYYY): ...</em></p>`, NL `<p><em>Update (D maand YYYY): ...</em></p>`, using today's date (Europe/Amsterdam), and add its source to "sources". Do not add updates for minor developments.
- Strictly own words, no copied sentences, no invented facts or quotes.

## 2. Restructure the body (en and nl) to the storyline
- Intro paragraph(s) give the key facts and end with a clear problem, stated as a plain statement (never as a question: the heading is the question).
- Then 4-6 `<h2>` headings phrased as the QUESTION that problem raises (EN "So how does ...?", "Why ...?", "What ...?"; NL "Hoe ... dan?", "Waarom ...?").
- Each section starts with the direct answer in bold: `<p><strong>Short answer.</strong> explanation...</p>`, and ends with the next problem, stated as a plain statement (never as a question), that leads to the next heading.
- Keep the same facts (after your fact check), roughly the same length (±20%), keep lists as `<ul><li>`, keep the financial-advice disclaimer if present, keep the article readable as a normal written article. Dutch must be natural fluent Dutch, Dutch number formats.
- Do NOT change: slug, date, time, category, models, images, label, title, description (only change title/description if they contain a factual error), and keep "short" as is unless it contains a factual error (then fix that error in it).

## 3. Add "video"
Add `"video": {"en": [...], "nl": [...]}` exactly per the writing rules below: blocks {"text"}, {"head"} (exactly the h2 text), {"key","text"} for list items, optional "img" lists with photo files from PHOTOS.md (in the repo root) whose subject really matches; give each head an img and use 6-12 different fitting photos overall where enough fitting photos exist (fewer is fine for narrow topics; never use a photo of a different product). Same order, headings and facts as the body. Write for the ear, numbers as digits, NL "één" with accents when it means one. No "trendingtesla.com".

## 4. Validate
After writing each file, run: `python3 -c "import json,sys;a=json.load(open(sys.argv[1]));assert a['video']['en'] and a['video']['nl']" <file>` and check that every head in video equals an h2 in the body of the same language (strip tags), and that every img file exists (either in static/img/ or the path referenced in PHOTOS.md — check how existing articles reference them).

## 5. Report
Append to your report file (path given in your task) one block per article:
```
## <slug>
- Fact check: OK | corrected: <what, with source URL> | update added: <what>
- Unverifiable/softened: ...
```
Keep it short. Your final message: the number of articles done and a bullet list of only the substantive corrections/updates (not "OK" ones).
